- Destinatário independente: `contato@ogritech.com.br` (`37ee0b4d-da17-419f-a0c0-767f8f52725d`).
- Envio: convite criado às 20:33:38 UTC; `invited_at` e `confirmation_sent_at` confirmados no banco. O Auth registrou `user_invited`, `POST /invite`, HTTP 200 às 20:33:40 UTC, com o redirect de staging esperado.
- Entrega: mensagem `You've been invited` confirmada na caixa Zoho do destinatário às 17:33 BRT, remetida pelo SMTP próprio configurado.
- Aceite: a primeira abertura retornou `Bad Gateway` antes de alcançar o Auth. Sem consumir o token, a nova tentativa concluiu o convite; `email_confirmed_at = 2026-08-27 20:36:27 UTC` e `last_sign_in_at = 2026-08-27 20:37:23 UTC`.
- Perfil: como o convite de validação foi disparado diretamente pelo painel Auth, foi necessário criar explicitamente `public.profiles` e `public.platform_admins` para o administrador global de staging, sob autorização do proprietário. A auditoria posterior encontrou zero usuários Auth sem perfil e zero perfis sem usuário Auth.
- Prevenção: `platform-users` versão 5, já publicada no staging, passou a retornar `auth_users_without_profile`. O código do console administrativo foi atualizado para interromper o carregamento com orientação operacional caso a divergência reapareça e entrará no host no próximo deploy do site. O runbook determina que convites da aplicação sejam enviados somente pelo console Ogritech/Edge Function, pois o painel Auth não conhece função nem empresa.
- Verificação local da prevenção: `npm test`, 10/10 testes aprovados.
- Resiliência do painel: após um login válido, duas validações administrativas no navegador falharam antes de alcançar a API; a simulação SQL com o mesmo `sub` e papel `authenticated` retornou `is_platform_admin = true`. O console foi ajustado para repetir a RPC em até três tentativas (`0`, `300` e `900` ms), sem relaxar a autorização.
- Causa raiz da falha no painel: a CSP em `admin.html` ainda autorizava somente o projeto Supabase de produção. O endpoint HTTPS/WSS de staging foi incluído explicitamente e o cache-busting do script foi atualizado para `admin.js?v=20260827.1`.
- Publicação e smoke test: commit `97a486d` publicado no `main`. O host carregou `supabase-js 2.112.3` e `admin.js?v=20260827.1`; `contato@ogritech.com.br` foi exibido como `Administrador de staging`, a validação terminou e o painel administrativo ficou acessível sem novo erro.
